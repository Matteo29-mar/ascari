update 24/06/2026
1. fatto un po di modifiche e risolto un po di errori:
1️⃣Problema: Errore 404 – Richiesta fallita su MyGarage. La pagina MyGarage effettuava chiamate a endpoint non coerenti con le route backend (path errato o non registrato), generando 404.
Soluzione: Allineamento delle route frontend con quelle realmente esposte dal backend e verifica della registrazione corretta dei router Express.
2️⃣Problema: Errore 400 – Risorse non trovate / ID non valido Richieste del tipo /api/chat/undefined o ID non numerici generavano errori 400 o crash Prisma (id mancante/NaN).
Soluzione:Validazione preventiva degli ID lato backend. Controllo e sanitizzazione degli ID lato frontend prima di chiamare le API. Blocco delle chiamate se il parametro non è valido.
3️⃣Problema: Calendario – Miglioramento UI e colori Gli slot nel calendario non avevano differenziazione visiva chiara e non comunicavano bene lo stato.
Soluzione:Introduzione di colori e miglioramento della resa visiva degli eventi FullCalendar per distinguere meglio disponibilità e stato.
4️⃣Problemi: Problemi strutturali in chat.ts (backend)Mancata validazione dell’ID chat. Prisma crashava su findUnique con ID invalido. Mancata gestione coerente dello stato CANCELLED. Chat visibili anche quando non dovevano esserlo.
Soluzione:Funzione centralizzata per parsing sicuro dell’ID. Blocco apertura chat al periziatore se perizia annullata. Filtro in lista chat per nascondere chat CANCELLED al periziatore. Migliore gestione permessi buyer/seller.
5️⃣ Problemi in chat.tsx (frontend pagina chat) Polling attivo anche con ID non valido. Chiamate ripetute verso /chat/undefined. Mancata gestione elegante degli errori 403/404.
Soluzione:Validazione preventiva del chatId. Blocco polling se ID non valido. Redirect automatico alla lista in caso di errore. Gestione popup per chat cancellate.
6️⃣ Problemi in chatlist.tsx La lista chat generava richieste con ID undefined e link non validi.
Soluzione:Pulizia e normalizzazione del payload backend.Filtro hard sulle chat senza ID valido. Rimozione di qualsiasi chiamata diretta a /chat/:id nella lista.
7️⃣ Problema:Dopo annullamento perizia, la chat rimaneva visibile a entrambi o non era coerente con le regole di business.
Soluzione:Regola: chat CANCELLED visibile solo al venditore. Blocco apertura e invio messaggi per il periziatore. Introduzione endpoint DELETE per eliminazione manuale. Popup lato venditore per gestione eliminazione.
